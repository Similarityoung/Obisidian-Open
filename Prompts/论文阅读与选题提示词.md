# 论文阅读与选题提示词

## 阅读研究论文

请根据我提供的论文，用中文分析下面的内容。重点讲清方法，区分论文结论、你的推断和缺失的信息。

1. **摘要与问题**：翻译摘要，说明作者要解决什么问题、现有方法的局限，以及提出方法的动机。
2. **方法流程**：按“输入 → 处理 → 输出”逐步解释模块、公式和算法。具体到每一步做什么、为什么这样做，以及模块如何配合。
3. **方法对比**：与论文中的主要对照方法相比，差别、贡献和适用范围是什么？必要时用表格。
4. **实验与局限**：说明数据集、指标、对照和消融实验，引用关键结果，分析计算成本与适用边界。
5. **复现与应用**：指出开源代码、数据预处理、超参数和实现要点；分析能否迁移到我的任务。
6. **便于回忆的概括**：一句话概括核心思想，再用 3–5 个直白步骤复述流程，不使用比喻。

没有论文原文或相应证据时，明确说明无法确认，不补造实验数据。

## 阅读综述

请根据我提供的综述，用中文梳理：

1. 标题、作者、年份、发表渠道，以及覆盖的任务范围。
2. 研究背景、应用需求和综述要回答的问题。
3. 作者的方法分类、各类代表工作，以及相互联系和演化过程。
4. 各类方法的优势、限制和适用场景。
5. 作者提出的挑战、趋势和未解决问题。
6. 对我的研究方向 `[填写方向]` 有何启发，可使用哪些数据集、代码或工具。
7. 提炼核心术语和方法速览表；有明确演化关系时再画时间线。

## 筛选可改进的研究基线

研究方向：**Document-centric RAG + Knowledge Graph**。目标是在有限算力和工程时间下，找到可以复现、修改并验证的硕士论文课题。

约束：

- 以“文档 → 文档块 → 证据”为主，不做传统 KGQA。
- KG 用于结构约束、导航、扩展、剪枝或调度。
- 不依赖大模型微调、GNN 训练或大规模算力。
- 方法中应有可独立修改的流程、图算法、索引或检索环节；避开只能照搬整套系统的工作。

对每篇论文，说明：

1. 论文身份与来源；一句话讲清实际解决的问题。
2. KG 在索引、检索、后处理或调度中的具体作用。
3. 是否适合做可修改基线，以及复现成本和限制。
4. 1–3 个具体改动点，例如全局图改为查询局部图、硬过滤改为软评分、离线构建改为按需构建。
5. 每个改动要验证的假设、对照实验和潜在失败原因；可拟一个研究标题，但不要把设想当成已经成立的创新。

最后给出最多 3 篇优先候选、仅适合对照的工作，以及 2–3 个研究方向，注明借鉴来源与改动环节。候选不足时不要凑数。
